# Task 4 API — FastAPI и PostgreSQL pool

Приложение из `Assignment_API.pdf`. Основной код находится в `app.py`.
Один процесс Uvicorn создаёт один общий pool, максимум **5 соединений**.
API запускается, даже если PostgreSQL выключен.

## Запуск

Нужны Docker с Compose и Python 3 для автоматической проверки.

```bash
cd /home/beknur/devops1/lecture-7/task4-api
python3 -c 'import secrets; open(".env", "x").write("POSTGRES_PASSWORD=" + secrets.token_hex(24) + "\n")'
chmod 600 .env
docker compose up -d --build
curl http://localhost:8000/health/live
curl http://localhost:8000/health/ready
curl http://localhost:8000/db-time
```

Команда создания `.env` нужна один раз. Она не перезаписывает существующий файл.
Пароль хранится только локально: `.env` исключён из Git и Docker image.
PostgreSQL доступен внутри Compose-сети, его порт на хост не публикуется.
Если порт 8000 занят, добавь `API_PORT=8001` в `.env` и используй этот порт в curl.

## Что делает код

`lifespan()` создаёт pool при запуске и закрывает его при завершении приложения.
`min_size=0` позволяет создать pool без подключения к БД. Соединения появляются
при запросах и используются повторно. `max_size=5` ограничивает их количество.
В Dockerfile задан `--workers 1`; несколько workers создали бы несколько pools.

`query_value()` берёт соединение из общего pool, выполняет SQL и возвращает
соединение. Ошибки подключения и таймауты превращаются в HTTP 503.
На получение соединения отведена 1 секунда, на SQL — 1 секунда, на возврат/reset
соединения — ещё максимум 1 секунда. Это оставляет запас до ограничения 5 секунд.
Отдельный connect timeout также равен 1 секунде и входит во время acquire.
Негодные соединения asyncpg закрывает; следующие запросы подключаются заново.
Для восстановления не нужны restart приложения или container restart policy.

| Endpoint | Что делает | Без PostgreSQL |
| --- | --- | --- |
| `/` | Возвращает сообщение и версию приложения | 200 |
| `/health/live` | Проверяет работу HTTP, без обращения к БД | 200 |
| `/health/ready` | Выполняет `SELECT 1` через pool | 503 |
| `/db-time` | Выполняет `SELECT NOW()` через pool | 503 |
| `/pool-stats` | Показывает size, idle и max_size pool | 200 |

Настройки подключения берутся из `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`,
`PGPASSWORD`. При отдельном запуске можно вместо них передать `DATABASE_URL`.
Compose задаёт переменные PG автоматически.

## Проверка задания одной командой

```bash
python3 verify.py
```

Скрипт создаёт отдельный Compose-проект со случайным именем, паролем и свободным
локальным портом. В конце удаляет только созданные им контейнеры, сеть и volume.
Он не останавливает обычный проект, запущенный командой выше.

Проверка выполняет все четыре состояния из PDF: API без БД, запуск БД,
повторная остановка БД, восстановление БД. Для каждого состояния проверяются
HTTP-коды и время ответа меньше 5 секунд. Дополнительно `docker pause` проверяет
зависшую БД с открытыми TCP-соединениями.

Затем одновременно отправляются 20 запросов `/db-time`. Скрипт проверяет ответы,
снимает метрики `/pool-stats` во время запросов и считает соединения API через
`pg_stat_activity`. Значения должны быть не больше 5. Он также сравнивает
Container ID, StartedAt и RestartCount API до и после тестов и проверяет
закрытие всех соединений при graceful shutdown.

Проверено локально 21 октября 2026: все этапы пройдены; отказ при остановленной
БД занимал около 0,19 с, при `pause` — максимум 2,01 с. Все 20 параллельных
запросов вернули 200; наблюдаемый размер pool и число PostgreSQL-сессий — 5.
API не перезапускался; после shutdown число его сессий стало 0.

Ручная проверка восстановления:

```bash
docker compose stop postgres
curl -i http://localhost:8000/health/live
curl -i http://localhost:8000/health/ready
curl -i http://localhost:8000/db-time
docker compose start postgres
curl -i http://localhost:8000/health/ready
curl http://localhost:8000/db-time
curl http://localhost:8000/pool-stats
```

После `start` БД может потребоваться несколько секунд; повтори запрос ready.

## Ответы на вопросы

**Liveness** означает, что приложение работает и отвечает на HTTP.
**Readiness** означает, что оно может выполнять полезную работу с зависимостями.
Поэтому при падении PostgreSQL liveness остаётся 200, а readiness становится 503.

**Если все 5 соединений заняты**, новый запрос ждёт освобождения одного из них
до 1 секунды. Если соединение освободилось — запрос выполняется; если время
истекло — возвращается 503. Шестое соединение не создаётся.

Остановка:

```bash
docker compose down
```

Документация: [asyncpg — pool, acquire и release](https://magicstack.github.io/asyncpg/current/api/index.html#connection-pools).
