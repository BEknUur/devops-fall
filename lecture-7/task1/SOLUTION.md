# Как работает Task 1

API уже есть в `app.py`. В нём нет ротации, файлов логов или systemd:
вся настройка находится снаружи приложения.

```text
simple-api.service
    └── uvicorn app:app
          └── stdout + stderr → /home/logs/app.log

logrotate-api.timer (раз в 5 секунд)
    └── logrotate-api.service
          └── /usr/local/bin/simple-api-rotate (копия rotate.sh)
                ├── размер >= 1 MiB → копировать и обнулить лог
                └── дата + длительность → /home/log_rotates.log
```

## Зачем нужны разные файлы

| Файл | Что делает |
| --- | --- |
| `app.py` | Отвечает на `/`, `/health`, `/items/{item_id}` |
| `requirements.txt` | Фиксирует прямые зависимости API |
| `simple-api.service` | Запускает API, направляет логи в файл, задаёт лимиты |
| `rotate.sh` | Проверяет размер, сохраняет две копии и обнуляет текущий лог |
| `logrotate-api.service` | Однократно запускает скрипт и сохраняет его вывод |
| `logrotate-api.timer` | Запускает сервис ротации примерно раз в 5 секунд |
| `setup.sh` | Устанавливает файлы и запускает сервисы |

## Главное в systemd

`StandardOutput=append:/home/logs/app.log` направляет stdout в файл с дописыванием.
`StandardError=inherit` направляет stderr туда же. systemd открывает файл до
запуска API, поэтому процесс может работать под `DynamicUser=yes`.

`Type=oneshot` означает: запустить скрипт и дождаться его завершения.
Таймер и сервис имеют одинаковое имя `logrotate-api`, поэтому таймер знает,
какой сервис вызвать. `OnActiveSec=5s` задаёт первый запуск через 5 секунд,
`OnUnitInactiveSec=5s` — следующий через 5 секунд после завершения скрипта.

## Зачем копирование и обнуление

Если просто переименовать текущий лог, работающий процесс продолжит писать
в старый открытый файл. Поэтому мы копируем содержимое в архив и обнуляем
исходный файл командой `truncate -s 0`: открытый файл остаётся тем же.

Текущий лог плюс две копии — всего три файла. Дата и длительность попадают
в отдельный файл `/home/log_rotates.log` через перенаправление systemd.

Размер проверяется периодически, поэтому 1 MiB является порогом, а не строгим
ограничением каждого байта. Возможна потеря строк между копированием и
обнулением. Команды установки, проверки и ограничения описаны в `README.md`.
